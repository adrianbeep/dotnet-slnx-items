## What changed

Reads a `.slnx-items.yaml` manifest per `docs/design/manifest-schema.md` and applies its declared folder + file set to the solution via `SolutionItemsService.AddFolderAsync` + `AddFilesAsync`. - New `src/DotnetSlnxItems.Cli/Paths/YamlManifestReader.cs` (~150 lines, `internal static class`): reads the manifest via `YamlDotNet 18.1.0` (`DeserializerBuilder().WithNamingConvention(UnderscoredNamingConvention.Instance).Build()`), deserializes into `Dictionary<string, List<string>>` internally (records with positional ctor params aren't constructible by YamlDotNet), then walks the raw `YamlStream` to reject anchors, aliases, flow-style mappings/sequences, multi-document payloads, and explicit tags. Throws `SolutionItemsException(InvalidManifest)` with 1-indexed `(line, column)` on any `YamlException` (the underlying API is 0-indexed). - New `src/DotnetSlnxItems.Cli/Commands/SyncCommand.cs` (~340 lines, `public static class`): `Create()` factory mirroring `AddFolderCommand.Create()` byte-for-byte with three options (`--manifest|-m`, `--solution|-s`, `--dry-run`). Non-static `SetAction(parseResult => RunAsync(...))` because `System.CommandLine 2.0.12` has no static 3/4-arg overload (matches #42/#43/#48). Private `RunAsync` wraps `RunCoreAsync` in a top-level `try { ... } catch (SolutionItemsException ex) { ErrorMapper.Map -> stderr + exit code }` so uncaught Core throws bubble out as exit codes instead of "Unhandled exception: ..." runtime output. Flow per spec #1108: (1) resolve manifest path (`explicit ?? Path.Combine(cwd, ".slnx-items.yaml")`; `!File.Exists` → `ManifestNotFound`); (2) `YamlManifestReader.Read`; (3) pre-flight per entry: folder key non-empty + no `..`/leading `/` → `InvalidManifest`; file relative → `InvalidManifest` if rooted; file exists on disk (resolved via `Path.GetFullPath(Path.Combine(manifestDir, file))`) → `FileReferencedInManifestNotFound` if missing; (4) solution resolution (`SolutionResolver.ResolveFromCwd` null → CLI exit 2; `SolutionItemsService.CreateAsync` → `ErrorMapper` exit 4 for `.slnf`); (5) `await service.ListAsync()` single fetch; (6) partition via two `HashSet`s — `existingFolders` (folder paths) and `existingFiles[folderPath]` (per-folder file sets) tracked by walking the flat item stream; (7) diff — `foldersToCreate = keys not present`, `filesToAdd = per partition miss` (a missing folder makes every file a miss); (8) `--dry-run` prints `[DRY-RUN] Would create folder '<path>'` and `[DRY-RUN] Would add file '<folderKey>/<file>'` per change + `[DRY-RUN] Would sync F folder(s) and N file(s).` summary, returns 0 without `AddFolderAsync`/`AddFilesAsync`/`SaveAsync`; (9) apply calls `AddFolderAsync` per folder (filters `FolderAddResult` records to `record.Path == normalizedKey && record.Created` to suppress ancestor records like `/docs/` when key is `docs/infrastructure`), `AddFilesAsync` with absolute paths (catches `InvalidFilePath` and re-throws as `InvalidManifest` per `manifest-schema.md:122-124`), one `SaveAsync` at the end, prints `Synced F folder(s) and N file(s).` summary. Empty manifest (`Folders.Count == 0`) takes a fast path: no output, return 0 (test `Sync_EmptyManifest_NoOutputExitZero`). Singular/plural: `Synced 1 folder and 0 files.` (one folder, zero files), `Synced 3 folders and 6 files.`. 1. **Apply-phase verification of the schema-spec prerequisite.** Issue #11 depends on the schema spec from #10 / PR #53. Cite design #1109 §Commit Plan.
2. **CLI-side diff via `ListAsync` partition (cite proposal #1107 decision #1).** No new Core method was added; `SolutionItemsService` already exposed `ListAsync`, `AddFolderAsync`, `AddFilesAsync`, and `SaveAsync`. The CLI builds the diff locally so the issue body's wording ("Calls `SolutionItemsService.AddFolderAsync` for missing folders and `SolutionItemsService.AddFilesAsync` for missing files") is implemented literally. The minimum Core surface — `SolutionItemsManifest` record + 3 enum members — is exactly what's needed to ship the manifest shape.
3. **YamlDotNet 18.1.0 record-deserialization caveat.** YamlDotNet 18.x cannot construct a record with positional ctor params (the type has no parameterless ctor). `YamlManifestReader` deserializes into `Dictionary<string, List<string>>` internally (the concrete types YamlDotNet can populate) and then constructs the `SolutionItemsManifest` record manually via `Normalize`. The public API (`IReadOnlyDictionary<string, IReadOnlyList<string>>`) is unchanged from design #1109 §Public API Surface Delta; the API contract is honored through the explicit `Normalize` mapping. The empty-folder fixture (`slnx-items-empty.yaml`) hits the `null → Array.Empty<string>()` branch.
4. **Strict subset enforcement via post-walk.** YamlDotNet 18.x does not reject anchors, flow style, multi-doc, or explicit tags at parse time. `YamlManifestReader.ValidateSafeSubset` walks the parsed `YamlStream` after deserialization and throws `InvalidManifest` for any of those constructs (cite `manifest-schema.md:65-78`). Tests 12 (`slnx-items-bad-yaml.yaml` — unclosed flow bracket) and 14 (`slnx-items-absolute-path.yaml` is a valid manifest but rejected at pre-flight, not at parse time) cover the boundary.
5. **`System.CommandLine 2.0.12` `SetAction` 4-arg shape.** Non-static capturing lambda `parseResult => RunAsync(parseResult, manifestOption, solutionOption, dryRunOption)` (matches the `AddFolderCommand.cs:37` and `ListCommand.cs:73` precedents). The 3-option verb exceeds the static-arg overload set in `System.CommandLine 2.0.12`, so a capturing lambda is required; `dotnet format` leaves it untouched because the lambda body is a single method call.
6. **Manifest folder-name filter for the `Created folder` line.** `AddFolderAsync` cascades ancestors — `docs/infrastructure` returns `FolderAddResult` records for `/docs/`, `/docs/infrastructure/`. The CLI filters to `record.Path == NormalizeFolderPath(manifestKey) && record.Created` so the user only sees the folder they declared (cite `manifest-schema.md:39-47` and the test 5 assertion `Created folder '/docs/infrastructure/'.`). Test 5 verifies the ancestor suppression by asserting `Created folder '/docs/'.` is NOT present in stdout.
7. **File-not-on-disk semantics.** The CLI pre-flight (step 3 in the run-flow) fires `FileReferencedInManifestNotFound` BEFORE any `AddFolderAsync`/`AddFilesAsync` call, satisfying the "no partial state saved" rule from `manifest-schema.md:121, 130`. Test 13 (`Sync_FileNotOnDisk_NonZeroExitStderrNamesFile`) asserts the offending path appears in stderr.
